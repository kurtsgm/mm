# 動作提交、內容入口與敘事執行

此調整承接 `game-flow.md` 的輸入控制權與 `world-state.md` 的世界狀態分層。

## 3. 資源動作：驗證後提交

`ActionResult` 明確提供 `ok`、`reason`、`events`。訊息是給玩家的描述，不再用「訊息是否為空」推論成功或決定成本。

| 動作 | 驗證／提交的負責者 | 成功時 |
| --- | --- | --- |
| 野外治療／復活 | `FieldSpellAction` | 驗證清醒、已學會、SP、可生效目標後，扣一次 SP 並套用效果 |
| 回城 | `main._cast_world_spell()` | 驗證角色、選單模式與入口存在，取得轉場控制權，再扣 SP；隨後非同步演出轉場 |
| 戰鬥施法 | `CombatSystem.party_cast()` | 驗證目標後才扣 SP／推進回合，回傳 ActionResult |
| 消耗品 | `ItemUseAction`；戰鬥由 `party_use_item()` 編排 | 驗證背包數量與目標，同步扣道具／套效果；成功才推進回合 |
| 商店 | `VendorTransaction` | 驗證定義、價格、持有物、學習資格或服務目標，提交金幣與物品／角色變更 |
| 對話選項 | `DialogueRunner` → `StoryEffects` | 重新確認選項仍可用、預檢整批成本，成功才提交並移動對話節點 |

角色面板以同步 callable 請求世界法術結果，收到成功後才關閉；不自行扣 SP。尚未實作的 TELEPORT 明確回報失敗，保留 SP 與選單。旅行目的地遺失時釋放已關閉旅行畫面的控制權。

`StoryEffects` 在任何寫入前預算整批金幣與道具餘額，因此「先扣錢、給物、設旗標，最後才發現缺另一件物品」不會留下部分變更。資源與旗標提交完成後才通知任務，讓任務評估看到完整批次。重複選擇舊節點或條件已失效的選項不會重複扣款。

這裡的原子性是同步遊戲命令的驗證與提交；不跨越整段含 await 的過場做回滾。過場若後續步驟失敗，先前已成功的故事命令仍有效，但此次場景不會記為已完成。新增效果必須先加入批次驗證，不能在提交途中新增會失敗的外部操作。

## 4. 遊戲資料註冊表

`content/registry.json` 是道具、法術、遭遇組、地圖、任務、對話、商店、過場、旅行網與大陸資料的路徑入口。`ContentRegistry` 負責 ID 查找和檔案讀取；`engine/content/` 的型別目錄負責解析為 ItemDef、SpellDef、QuestDef 等。

原本在 presentation 的 9 個遊戲資料目錄已移至 engine/content。美術、模型、肖像與主題目錄仍由 presentation 負責；職業、詞綴等規則表留在各自的 engine 模組。這不是把所有規則塞進同一份 JSON。

新增內容：

1. 建立內容檔，將 ID 與路徑加入 registry 的對應類別。
2. 以對應型別目錄讀取，呼叫端不拼接路徑。
3. 跑 `godot --headless --path . --script tools/content_lint_cli.gd`，檢查型別、ID、跨檔依賴與地圖入口。
4. 涉及任務時再跑 `tools/quest_lint_cli.gd`，驗證任務目標及實際完成流程。

未知 ID 回傳缺失結果；JSON 載入失敗不把解析錯誤混入遊戲輸出。registry 查詢不暴露可修改的內部表。

## 5. 敘事執行與演出分離

- `GameState` 持有可存檔的 quests、flags、triggered_scenes 等狀態與對外查詢。
- `NarrativeRuntime` 負責接任務、推進、追認、獎勵、通知及建立場景執行紀錄。`QuestSystem` 保持純粹的階段計算。
- `StoryEffects` 是對話和過場共用的故事命令入口，不重複實作旗標、道具與任務效果。
- `NarrativeScene` 在開始時捕捉原生地圖、格子與 once 規則。只有 `complete(true)` 消耗 once；失敗可重播，重複完成不重複紀錄。
- `CutscenePlayer` 播放視覺、聲音與對話，將故事效果交給 StoryEffects。播放前先確認必要對話存在；步驟失敗時停止、清理黑幕與暫態畫面，回傳失敗。main 根據結果收尾，輸入仍由 GameFlow 管理。

任務狀態、故事旗標與已完成演出仍是不同事實：旗標不等於任務階段，開始播放也不等於完成場景。過場內對話結束時不釋放外層過場控制權。
