# 裝備：詞綴 × 品質 × 等級門檻掉落系統 — 設計

**日期**：2026-07-04
**狀態**：設計核可，待轉 writing-plans
**範圍**：完整可玩（資料模型 + 掉落生成 + 背包/裝備/存檔實例化 + UI + 一批內容 + 商店買賣）

## 1. 目標與動機

把目前「一件裝備＝一個固定 `.tres` id」的極簡模型，升級為 wow/diablo 風格的
**隨機詞綴 × 品質階 × 等級門檻掉落**系統：

- 同一把 base（如鐵劍）每次掉落可帶不同品質與不同詞綴組合、不同數值。
- 品質階決定詞綴數量與稀有度；傳說品質改抽手工專屬物件（unique）。
- 強力 base 有「等級帶」門檻——例如某武器只在 lv50–60 的怪／地下城掉落。
- 地下城比野外更容易掉高品質。

### 核心決策（已與使用者確認）

| # | 決策 | 選定 |
|---|------|------|
| 1 | 底層模型 | **混合實例化**：消耗品維持 id-count 堆疊；裝備改成「base + 品質 + 隨機詞綴」的 `ItemInstance` |
| 2 | 品質階數 | **4 階**：白 普通(0 詞綴) / 綠 精良(1) / 紫 稀有(2–3) / 橙 傳說(4–5 + 專屬) |
| 3 | 詞綴結構 | **前綴 + 後綴 + 傳說專名**：詞綴分前/後綴、各自拼進物品名；傳說改用手工命名的 unique |
| 4 | 等級門檻 | **連續等級帶 + tier 品質權重**：每個 base 標 `min_level/max_level`；品質權重隨怪物 tier 提升；地下城額外加成 |
| 5 | 詞綴 stat 域 | V1 **全開**（attack/armor/七屬性/hp_max/sp_max）＋武器 on-hit 異常詞綴＋防具抗性詞綴 |
| 6 | 固定掉落 | `MonsterDef.drop_item_id` **保留**，語意收斂為「固定消耗品/任務物掉落」；程序化裝備另走 `LootRoller` |

### 專案前提

- **pre-release，不需向後相容**：存檔直接升版（v11 → v12），不寫相容/遷移層；一併更新所有呼叫端與既有 content/test 資料。
- UI 一律**比例式版面**、對使用者的說明一律**繁體中文**。
- 純邏輯留在 `engine/`（id/資料導向，RNG 注入以利可重現與模擬）；載入/呈現留在 `presentation/`。

## 2. 資料模型

### 2.1 `ItemDef`（既有 `resources/item_def.gd`，擴充欄位）

仍是「base 模板」：固定名稱、基礎數值、掉落資格。新增：

```gdscript
@export var min_level: int = 1       # 這個 base 最早出現的怪物等級
@export var max_level: int = 999     # 最晚出現（強力 base 設窄帶，如 50~60）
@export var drop_weight: int = 0     # 進程序掉落池的權重；0 = 不參與程序掉落（任務/商店專屬）
@export var slot_tag: String = ""    # 細分（sword/axe/…）；V1 不使用，預留
```

`attack`/`armor`/`value`/`category`/消耗品欄位照舊。**消耗品完全不動。**

### 2.2 `ItemInstance`（新，`engine/inventory/item_instance.gd`，`RefCounted` 純邏輯）

背包裝備欄位與裝備欄真正存放的東西。白裝＝品質 `COMMON`、零詞綴的實例。

```gdscript
class_name ItemInstance
extends RefCounted

var base_id: String            # → ItemCatalog 解析出 ItemDef（基礎 attack/armor/名字/售價）
var quality: int               # Quality 索引 0..3
var ilvl: int                  # 物品等級（顯示、售價、詞綴門檻）
var affixes: Array             # [{id, kind, mods:{stat_enum:int,...}, on_hit?, resist?}, ...]（已 roll 定的具體值）
var unique_id: String = ""     # 非空 → 走 UniqueCatalog 的專屬物件（專名 + 固定 mods/on_hit）
```

方法：
- `display_name() -> String`：`[前綴] base [後綴]`，unique 時回專名。
- `total_attack() / total_armor() -> int`：base + 各詞綴同項加總。
- `total_stat(stat_enum) -> int`：把某 stat 的 base + 詞綴貢獻加總。
- `weapon_on_hit() -> Dictionary`：武器 on-hit 異常（kind/potency/duration/chance），無則空。
- `resist_bonus() -> Dictionary`：防具/飾品的抗性加成（Element → %）。
- `sell_value() -> int`：`base.value × Quality.value_mult(quality)`，並依 ilvl 微調。

> **取捨**：affix 存「roll 完的具體數值」而非「id + seed」。顯示穩定、存檔自足、不綁詞綴表版本（契合「不需向後相容」）。

### 2.3 `Quality`（新，`engine/inventory/quality.gd`，const 表；仿 `MonsterTiers`）

| idx | id | 名 | 色 | 詞綴數 | 售價× | 掉落權重基準 |
|-----|------|------|-----|--------|-------|--------------|
| 0 | common | 普通 | 白 (#c8c8c8) | 0 | 1.0 | 保底 |
| 1 | fine | 精良 | 綠 (#4caf50) | 1 | 1.5 | 高 |
| 2 | rare | 稀有 | 紫 (#9c27b0) | 2–3 | 3.5 | 低 |
| 3 | legendary | 傳說 | 橙 (#ff9800) | 4–5 + 專屬 | 10 | 極低 |

介面：`Quality.affix_count(quality, rng)`、`Quality.color(quality)`、`Quality.value_mult(quality)`、
`Quality.display_name(quality)`。詞綴數落在區間者用注入 RNG 決定。

### 2.4 `AffixCatalog`（新，`engine/inventory/affix_catalog.gd`，const 表；仿 `Bestiary`）

```
id → {
  name: String,                 # 命名片段，如 "鋒利的" 或 "·熊之力"
  kind: int,                    # PREFIX=0 / SUFFIX=1
  applies_to: Array[int],       # 可掛的 ItemDef.Category（WEAPON/ARMOR/ACCESSORY）
  min_ilvl: int,                # 最早可出現的 ilvl（高階詞綴用較高值，分層）
  mods: Dictionary,             # stat_enum → [min, max]，roll 時取區間內整數
  on_hit: Dictionary = {},      # 武器 on-hit：{kind, potency, duration, chance}
  resist: Dictionary = {},      # 防具/飾品：Element → %
}
```

V1 詞綴 stat 域涵蓋：`attack, armor, might, intellect, personality, endurance, speed,
accuracy, luck, hp_max, sp_max`。前綴 ~10、後綴 ~10；含 2–3 個武器 on-hit（燃焰/淬毒/雷擊）、
2–3 個防具抗性。介面：`AffixCatalog.eligible(category, ilvl, kind) -> Array[id]`。

### 2.5 `UniqueCatalog`（新，`engine/inventory/unique_catalog.gd`，const 表）

```
id → { name, base_id, min_ilvl, mods, on_hit, resist }
```

傳說品質改從此表抽 ilvl 合格者。V1 手工 3–5 件；可輕掛世界觀（機制優先，不強掛）。
介面：`UniqueCatalog.eligible(ilvl) -> Array[id]`。

## 3. 掉落生成

### 3.1 `LootRoller`（新，`engine/inventory/loot_roller.gd`，純函式 + 注入 RNG）

系統心臟。輸入 `(monster_level, monster_tier, source, rng)`，輸出 `ItemInstance` 或 `null`：

```
1. 擲「是否掉裝」：gear_drop_chance（tier 給預設，MonsterDef 可覆寫）。未中 → null。
2. 選 base：從 base 池篩「min_level ≤ monster_level ≤ max_level 且 drop_weight > 0」，
   按 drop_weight 加權抽一個。（篩不到 → null）
3. ilvl = clamp(monster_level, 1, 100)。
4. 決定品質：查 tier → 品質權重表；source == DUNGEON 時權重整體上移（更容易紫/橙）。
5. 若品質 < 傳說：
   n = Quality.affix_count(quality, rng)
   從 AffixCatalog.eligible(base.category, ilvl, *) 篩，前/後綴各自去重、各上限 3 條，
   逐條在 mods 區間 roll 具體整數 → affixes。
6. 若品質 == 傳說：從 UniqueCatalog.eligible(ilvl) 抽一件（無合格者 → 降級為紫重走 5）。
7. 組出 ItemInstance 回傳。
```

純函式、RNG 注入 → 可用 `engine/sim` 模擬器驗證掉落曲線與 gear 強度；固定 seed 可做決定性測試。

### 3.2 品質權重表（`Quality` 內，初值待模擬器調校）

以怪物 tier(1–10) 為列、品質為欄的權重表；`source == DUNGEON` 時整體往高品質偏移
（實作為對 tier 加一個 offset 或套一張 dungeon 權重表）。範例意象：

- T1 野外：白 80 / 綠 18 / 紫 2 / 橙 0
- T6 野外：白 45 / 綠 37 / 紫 15 / 橙 3
- T6 地城：白 25 / 綠 40 / 紫 28 / 橙 7

### 3.3 怪物／地下城整合

- `MonsterDef`：`drop_item_id`/`drop_chance` **保留**＝固定消耗品/任務物；新增
  `@export var gear_drop_chance: float = -1`（-1 ＝用 tier 預設）。
- `LootSystem.roll_drops(monsters, source, rng)` 擴充回傳
  `{ item_ids: Array[String], instances: Array[ItemInstance] }`：
  既擲固定消耗品 id，也對每隻呼叫 `LootRoller` 產出 0..1 件裝備實例。
- **來源旗標**：戰鬥發起時帶 `source`（`OVERWORLD` / `DUNGEON`）。你舉的
  「lv50–60 才掉某武器」＝該 base 設 `min_level=50, max_level=60`，自然只在該等級帶的怪／地城掉。
- `presentation/world/main.gd::_grant_drops()` 改：消耗品 `inventory.add(id)`；
  裝備 `inventory.add_instance(inst)`，並推品質色 toast。

## 4. 屬性接通（重構半徑小）

現況：傷害/命中/防禦已全走 `attack_power()`/`effective_accuracy()`/`armor_value()`；
只有 `speed`（先攻/命中）與 `luck`（爆擊）直接讀原始欄位。

- `Equipment` 加 `total_stat(stat_enum) -> int`：跨已裝備實例把同 stat 加總（含 base attack/armor）。
- `Character`：
  - `attack_power()` / `armor_value()` / `effective_accuracy()` 各多加 `equipment.total_stat(...)`。
  - 新增 `effective_speed()` / `effective_luck()`；更新 `turn_order.gd`、`combat_system.gd`
    少數直接讀 `speed`/`luck` 的點改用之。
- `hp_max` / `sp_max` 詞綴：裝上→上限提高、當前值不變；卸下→上限降回、當前值 clamp 到新上限。
  由 `equip/unequip` 呼叫一個 `Character.recompute_caps()` 統一處理。
- `weapon_on_hit()`：接進戰鬥命中流程（複用既有 `StatusCatalog`/inflict 機制）。
- `resist_bonus()`：接進 `Resistance` 計算（角色端抗性目前無，V1 新增角色抗性彙總點）。

## 5. 背包／裝備／存檔（save v11 → v12，不做向後相容）

### 5.1 `Inventory`（混合）

- 消耗品維持 `_stacks`（id-count，不動）。
- 新增 `_instances: Array[ItemInstance]`（裝備，不可堆疊）。
- 新方法：`add_instance(inst)` / `remove_instance(inst)` / `instances() -> Array`。
- 既有 `add/remove/count_of/has/stacks/load_stacks` 不變。

### 5.2 `Equipment`

- 欄位改存 `ItemInstance`（原本存 `ItemDef`）。
- `can_equip(inst)` / `slot_for(inst)` 依 base ItemDef.category 判斷。
- `equip(inst)` / `unequip(slot)` 在 `Inventory._instances` 與欄位間搬移實例；觸發 `recompute_caps()`。
- `total_attack()` / `total_armor()` / 新 `total_stat()` 走實例。

### 5.3 存檔序列化（`SaveSerializer`，`VERSION = 12`）

- 實例 **inline 整包序列化**：`{base_id, quality, ilvl, affixes, unique_id}`。
- 背包：`_stacks`（如舊）＋ `instances` 陣列（inline）。
- 角色裝備：每欄 inline 存實例（取代原 slot→id）→ 無需交叉引用、無需 uid。
- 載入用既有 `ItemCatalog` resolver 解 base；實例自帶 rolled mods，統計自足。

## 6. UI（比例式版面 + 繁中）

- **物品名組字**：`[前綴] base [後綴]` 或 unique 專名；品質色套在所有裝備 Label
  （背包 `items_view`/`items_tab`/`items_confirm_dialog`、角色面板、隊伍 HUD、掉落 toast）。
- **明細/tooltip**：base 數值 + 逐條詞綴（＋力量 8、命中 +3、on-hit 灼燒…）+ ilvl + 售價。
- **裝備比較**：選裝備時顯示對當前裝備的 stat delta（±）。
- **掉落 toast**：`獲得 [紫] 鋒利的鐵劍·熊之力 (ilvl55)`（品質色）。

## 7. 商店

- 買基礎裝備 = 生成 `COMMON` 實例（0 詞綴）。
- 賣玩家實例 = 依 `sell_value()`（base value × 品質倍率 ± ilvl 微調）。
- vendor 框架／`add-vendor` 技能改認實例（買價看 base、賣價看實例）；武器店/防具店可上架白裝與少量綠裝。

## 8. 內容量（V1）

- **Base 池**：武器 ~8–10（木棍/短劍/鐵劍…鋼/秘銀/龍骨，含斧錘變化）、防具 ~6–8、飾品 ~3–5；
  既有 6 件裝備（short_sword/iron_sword/leather/chain_mail/buckler/lucky_charm）併入池並補
  `min_level/max_level/drop_weight`。
- **詞綴池**：前綴 ~10、後綴 ~10；含武器 on-hit 2–3、防具抗性 2–3。
- **傳說 unique**：3–5 件手工專屬，可輕掛世界觀。

## 9. 平衡與測試（TDD）

- 每個純單元先寫測試：`ItemInstance`、`Quality`、`AffixCatalog.eligible`、`LootRoller`、
  `Equipment.total_stat`、`Save v12` round-trip、`recompute_caps`。
- `LootRoller` 注入 RNG → 固定 seed 驗證品質/詞綴分佈與去重/上限。
- 掛進 `engine/sim` progression 模擬：驗證穿裝後隊伍強度曲線平滑、不破壞既有 combat-matrix；
  quality 權重/affix 數值/掉落率初值先給、由模擬器調校（比照 `MonsterTiers` 慣例）。
- （可選）內容 lint（仿 `check-quest`/`quest_lint`）：每個等級帶都有 base 覆蓋、無空池、
  affix `min_ilvl` 合理、unique base_id 存在。

## 11. 明確不做（YAGNI / 非 V1）

- 詞綴數值隨 ilvl 連續縮放（V1 用固定區間 + `min_ilvl` 分層即可）。
- 套裝（set bonus）、寶石鑲嵌、附魔/重鑄、耐久度。
- 物品實例 uid / 跨欄交叉引用（inline 序列化即可）。
- 存檔向後相容/遷移層。
- `slot_tag` 細分裝備欄（欄位預留、V1 仍三欄 WEAPON/ARMOR/ACCESSORY）。
